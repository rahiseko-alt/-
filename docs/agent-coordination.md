# Codex・Claude Code の連携方法

2026-10-08、ユーザーが「今後の運用を決めること」「ユーザーを伝言役にしないこと」を指示。

## 作業場所と担当

- Codex: `codex/layer1-replica`。専用ワークツリー `/workspace/DTP-codex-layer1`。Layer 1の画像・記録・配置の最小修正・出力・比較レビュー。
- Claude: `claude/*` の別ブランチ・別作業ディレクトリ。company-data・system・共通部品化。
- ワークツリーはブランチの切り替えや作業ファイルの干渉を防ぐ。共有ファイルの編集や取り込み時の競合は別途調整する。
- 別のクラウド環境では、このローカルパスの存在を前提にしない。担当ブランチを取得し、その環境の専用作業ディレクトリを使う。
- 担当外のファイルは変更しない。共有ファイルは引き継ぎで割り当てられた行だけを別コミットで変更する。

## 連絡の場所

- 作業状況・依頼・返答はGitHubに残す。ユーザーに相手へのコピーや伝言を頼まない。
- 通常は自分のドラフトPRを進捗の窓口とし、相手への具体的な依頼は相手の該当PRへコメントする。担当・対象ファイル・必要な対応・待つ必要があるかを明記する。
- PRがまだ作れない場合は、各担当が自分のブランチの `docs/coordination/<担当>.md` を更新してpushする。Codexのファイルは `docs/coordination/codex.md`。
- 他方の進捗ファイルを直接書き換えない。依頼への返答も自分の進捗ファイルへ、対象の依頼IDを付けて書く。
- 実際に送信できた記録と、相手の確認・返答を区別する。GitHubへのpushはClaudeの会話への直接送信や既読確認ではない。

## 各作業中の確認

セッション開始時、BOOKの切り替え時、コミット・PRの更新前に `git fetch origin` を実行する。
mainの更新と、相手が通知した担当ブランチの進捗を確認する。ローカルのファイルを上書きせず、`git show <相手の参照>:docs/coordination/<担当>.md` などで読む。
各自の担当内で完結する作業は相手の返答を待たずに進める。担当をまたぐ変更だけを依頼にし、その変更に依存しない作業は続ける。
現在の全ブランチを毎回無差別に読むことや、相手の会話の常時監視は前提にしない。

## mainと検証

Codexはmain `4048897` を取り込み済み。PR #10のマージによるQRの更新はa-admissions・b-living・b-flyerの再出力で確認する。
マージ前は最新mainを取り込み、doctor → check → 変更BOOKのrender → 目視・compareを完了する。生成指示が完了していないBOOKをgeneratedにしない。
規則・スキーマ・検証の変更はCodexが独断で行わず、必要な変更をClaudeへ依頼する。

## 現在の通信上の限界

この環境にはClaudeの実行中の会話へ直接送信する機能がない。GitHub APIも通信拒否（HTTP 403）のため、PR作成とコメント通知はまだ実行できていない。
Gitのfetch・pushは使用できるため、Codexの状況とClaude宛の依頼は担当ブランチへ公開する。
APIへの通信設定は下書きに保存済み。設定が適用されたら、既存の認証で接続を確認し、ドラフトPRと該当PRへの連絡を行う。認証不足が実際に確認されるまではトークンを要求しない。
相手に届いた、既読になった、運用への同意を得た、とは未確認のまま報告しない。
